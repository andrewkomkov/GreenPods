# WHAT IS VERBATIM, and what is not — this matters, because a fixture that overstates

#     * the four service ids 0x10..0x13 and their AccessoryService names
#     * the HeartRateService entitlement string com.apple.hid.heartrate-access
#     * the 126-byte heart-rate ReportDescriptor (see hr-report-descriptor.txt)
#
#   RECONSTRUCTED to the documented pattern, because the raw 996-byte frame was not
#   kept byte for byte:
#     * the property blob's D3 <count> header and its <u32 len LE> <type> <payload>
#       entries — the type bytes in particular are an inference from the shape
#       `<u16 keylen> 00 00 09 <ASCII key>` recorded in the notes
#     * the numeric property values, and the serial number, which is a placeholder
#     * the other three services' ReportDescriptor bodies, which were never decoded
#
# HidDescriptorParser is therefore written NOT to depend on the reconstructed parts:
# it takes the id from the protobuf, identifies the service by scanning the blob for
# ASCII literals, and locates the report descriptor by walking HID items rather than
# by trusting a type byte. A wrong guess here cannot make it wrong on a device.
